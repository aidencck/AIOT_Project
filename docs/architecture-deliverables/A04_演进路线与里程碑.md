## 架构变更主线

### Phase 1：收敛当前底座

- 重点模块：`gateway`、`auth-service`、`device-service`、`home-service`
- 演进模块：`rule-engine`、`shadow-service`、`mqtt-adapter`、`data-parser`
- 评审重点：
  - 服务边界是否稳定
  - 关键链路是否具备统一监控、回滚和验收口径
  - “可运行”和“可产品化”是否被清晰区分

### Phase 2：建立智能闭环

- 重点模块：`rule-engine`、`data-parser`、`device-service`
- 候选新增：`aiot-ai-service`、`aiot-ops-service`
- 评审重点：
  - `DeviceEvent` 是否统一
  - 设备数字体、知识切片、规则草案与审批是否形成闭环
  - AI 输出是否具备引用来源、风险等级和审计能力

### Phase 3：形成复制交付能力

- 重点模块：`ops-service`、`tenant-service`、模板与站点配置能力
- 评审重点：
  - 多租户/项目/站点边界是否清晰
  - 行业模板、初始化脚本、灰度回滚是否可验证
  - 交付能力是否标准化并能留档

### Phase 4：进入平台化运营

- 重点模块：开放接口、多角色工作台、行业方案包
- 评审重点：
  - 平台边界、开放能力、治理机制是否稳定
  - 规则、知识、执行反馈是否进入可持续迭代

## 里程碑评审模板

### 每阶段必填项

- 业务目标：本阶段解决什么业务问题
- 技术目标：本阶段收敛哪些架构或治理问题
- 架构变更：涉及哪些模块和边界
- 风险项：哪些高风险点需要前置控制
- 回滚点：失败时如何降级或回退
- Owner：业务 Owner / 架构 Owner / 工程 Owner
- Done 定义：何种证据算阶段完成

## 评审清单

- 是否与总路线图的阶段目标一致
- 是否满足 `A06_质量预算与SLO.md` 的预算约束
- 是否通过 `A07_治理门禁清单.md` 的发布门禁
- 是否在 `A08_验收报告模板.md` 中完成验收留档
- 是否具备可追溯的模块、接口、风险和回滚说明
