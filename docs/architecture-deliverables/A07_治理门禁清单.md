# A07 治理门禁清单

## 目标

- 将“架构要求”转为“发布门禁”，未通过门禁不得上线。

## 门禁清单（发布前）

| 分类 | 门禁项 | 通过标准 | 证据 |
| --- | --- | --- | --- |
| 契约治理 | 外部 API 返回统一 `Result` | 抽样接口 100% 符合 | 接口测试报告 |
| 身份治理 | 内部接口强制 `X-Internal-Token` | 抽样路径 100% 校验 | 单测/集成测试 |
| 调用治理 | `WebClient` 超时 + 有界重试 | 核心调用 100% 配置 | 配置与代码审计 |
| 事件治理 | Stream 消费 ACK + DLQ 处置 | 消费异常可追踪闭环 | 指标与日志 |
| 发布治理 | 单服务回滚脚本可执行 | 演练通过率 100% | 演练记录 |
| 观测治理 | 核心 SLO 有指标和告警 | 指标与告警规则齐全 | 看板截图/规则文件 |

## 门禁执行机制

- 阶段一：PR 检查（静态规则 + 单测 + 合约校验）。
- 阶段二：预发布检查（配置、链路、告警规则）。
- 阶段三：发布后观察（30 分钟关键指标守护）。

## 失败处置规则

- 任一 P0 门禁失败：立即阻断发布。
- 任一 P1 门禁失败：需架构 Owner 与业务 Owner 联合签署豁免。
- 任一 P2 门禁失败：允许上线但必须纳入下一 Sprint 整改。
