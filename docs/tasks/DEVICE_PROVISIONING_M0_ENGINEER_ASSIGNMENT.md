# 设备配网 M0 工程师分派执行单

## 1. Premise / Constraints / Boundaries / Endgame

- `Premise`：两周内完成设备配网 M0 可灰度上线，跑通“发起配网 -> 设备认领 -> 首次上线 -> 家庭绑定 -> 状态可见”闭环。
- `Constraints`：不新增微服务；优先复用 `aiot-device-service`、`aiot-home-service`、`aiot-auth-service` 现有能力。
- `Boundaries`：本期不做 Kafka 切换，不做多租户扩展，仅完成配网主链路、可靠性与可观测最小闭环。
- `Endgame`：形成可复制的配网交付模板（代码、脚本、监控、回滚齐备），作为后续规则引擎与 AI 场景接入底座。

## 2. 团队角色与责任

| 角色 | 人员代号 | 责任范围 | 交付物 |
|---|---|---|---|

## 5. 代码与模块分配

- `BE-1`：`aiot-device-service` 下 `ProvisionService`、`ProvisionController`、设备认领相关 DTO/Service。
- `BE-2`：`aiot-home-service` 下家庭绑定、成员权限校验、删除补偿接口。
- `BE-3`：`aiot-device-service` 与 `aiot-rule-engine` 的事件消费监听、pending recovery、DLQ 处理。
- `SE-1`：`aiot-auth-service` 与 `aiot-device-service` 的签名校验、防重放策略与配置模板。
- `QA-1`：`scripts/test_provision_and_webhook.sh` 扩展与回归用例落库。
- `SRE-1`：`docker-compose.yml` 环境配置基线、监控告警阈值、灰度回滚脚本。

## 6. 发布闸口（未达标禁止上线）

- 功能闸口：配网成功率 >= 98%，平均配网时长 <= 5s（内网环境）。
- 可靠性闸口：无未处理高优先级 DLQ 堆积，重复消费不产生重复绑定。
- 安全闸口：签名伪造、重放、超窗请求全部拒绝。
- 运维闸口：关键指标与告警上线，回滚脚本演练通过。

## 7. 阻塞升级机制

- `4小时` 内未解决的跨组阻塞：Owner 升级到 TL。
- `24小时` 内未解决的环境/发布阻塞：TL 升级到 SRE 与管理层协调资源。
- 任一上线闸口失败：自动触发“停止放量 + 回滚预案”。

## 8. 每日站会模板（15分钟）

- 昨日完成：仅报已合并或已验证结果。
- 今日目标：仅报可验收交付，不报研究性动作。
- 当前阻塞：明确阻塞人、阻塞项、期望解除时间。
- 风险预警：只报 P0/P1 风险及缓解动作。
